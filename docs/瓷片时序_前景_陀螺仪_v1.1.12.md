# 瓷片加载时序 / S1·S2 前景 / 陀螺仪：定位与方案（v1.1.12）
> 2026-11-12 · 环境：`dist/` 经 LAN 预览（iPhone Safari）+ headless Chromium 对照

## 1. 「拾得瓷片」时瓷片迟迟不出现

### 原因：面板同步建、图像异步等，中间没有占位

`showShard()` 先把**标题、史料卡、三个按钮**同步插入 DOM，而瓷片本体要等 `TQ.shardInner()`：

```
shardInner → TQA.resolve(key, cb)     // 内壁帧资产
           → cb('ok') 时才 mount.innerHTML='' 并 appendChild(canvas)
```

`TQA.resolve` 有 **2000ms 超时**；在这 2 秒里 `.shard-stage` 是**完全空的**。于是玩家看到的是「卡先出来、瓷片半天不来」，也就是"显示不同步"。

更糟的是：超时后返回 `timeout`，旧实现只画矢量占位，**图晚到也不会替换**——占位会一直留在屏上，直到重进界面。

### 实测（把内壁图响应延迟 2500ms 模拟慢网）

| 指标 | 修复前 | 修复后 |
|---|---|---|
| 面板出现 | 1ms | 1ms |
| 舞台首个内容 | ~2000ms（resolve 超时后） | **1ms**（矢量占位） |
| 真图替换占位 | 不会（永久占位） | **2116ms 自动升级** |

### 修复（`js/frag.js · TQ.shardInner`）

1. 进函数就 `vecShard(mount, false)` —— **同步画矢量轮廓**，零等待；
2. `resolve` 回 `ok` 时照旧清空并画真图（占位原位替换，不闪白）；
3. 回 `timeout` 时注册 `TQA.onLate(key, …)`，图晚到再走一遍（此时 `status` 已是 `ok`，`resolve` 同步返回）——**占位不会被永久留在屏上**。

### 还可以更快（未做）
- 幕开始时 `TQA.preload` 该幕涉及的 `shard-inner-*`（每张 23–40KB），把首帧等待进一步压到 0；
- 判据：`TQA.status[key]==='ok'` 时 `shardInner` 是同步的，不会有空窗。

## 2. 为什么"没有 S1、S2 的前景"

两件事，性质完全不同。

### S1：**未实现——缺资产**（不是被禁用）

- `def('s1_wanshou')` 的竖版是 `kind:'single'`，`files` 里只有 `main`（`l3v.webp`）；
- 现在屏幕上的"檐影/浮尘"是 `mountSingle` 里的**程序化 CSS 渐变**（`.tqs-solo-fg`），不是一张前景图；
- 渲染侧已留好接入位：`mountSingle` 支持可选 `files.fg` → `.tqs-solo-fgimg`（背景层，非 `<img>`，不吃长按）。
- 工作区确实没有可用透明前景：`s1_wanshou_p/keyed`、`shared` 为空；`l3v_gongmen` / `l3v_paichazhu` 是 780×1688 **整幅**（不透明约 66%），当前景会盖掉主图。

**实现思路**：出一张与主图同框（710×1475）的透明前景，内容取门楼近景（檐角/排叉柱剪影），透明区 ≥80%；文件放 `assets/scenes/s1_wanshou_p/l3v_fg.webp`，在 `def` 的 `v.files` 加一行 `fg: '…'` 即可，渲染不用动。

### S2：**已实现，但被 UI 盖住**（不是没加载）

- `s2_guangde` 横竖都注册了 `fg: l5v.webp`；
- 运行时验证：fg 层存在、在最上层（把它涂成红色 → 红色像素 100%），`mix-blend-mode:normal`，`opacity:1`；
- **但** `l5v.webp`（780×1688）不透明像素**只分布在 y1350–1688**（底部 20%，最后 169px 才 67% 实心）；
- 层是 114%（`top:-7%`），cover 后这块内容落在屏幕 **y≈734–903**；而对话框 / 占台面板正好覆盖底部约 250–300px ⇒ **勾栏被压在面板后面**。

**实现/修复思路（按优先级）**：

| 方案 | 做法 | 代价 |
|---|---|---|
| A 资产（推荐） | 把勾栏重导出到"可见带"：在 780×1688 里抬到 y≈1100–1350（屏幕上 ≈550–675），或直接出一张 390×844 构图的前景 | 需重出图；最干净 |
| B 结构 | 给 fg 单独一个"可见带容器"（高 = 舞台高 − 对话框高），按该带 `cover` | 改动渲染几何，需回归 4 个场景 |
| C 代码临时 | fg 层纵向拉伸到 128% + `background-position:50% 78%` | 勾栏会变形，只作过渡 |

> 结论：S2 不是"没做"，是"做了但构图落在被遮挡的区间"；S1 才是真的缺图。

## 3. 为什么没有陀螺仪效果

**已实现，但被运行环境禁用。**

- 链路：`tilt.js` → 检测不到 `window.xhs` 时按需加载 `js/tilt-web.js` → `OrientationSource` 监听 `deviceorientation`；
- iOS 13+ 的 `DeviceOrientationEvent.requestPermission()` 已写在 `tilt-web.js` 里，失败不致命，`tilt.js` 的 `retryOnGesture` 会在首次手势重试。

**当前不生效的三个条件**：

1. 本地预览是 `http://192.168.1.29:8931`——**非安全上下文**，iOS Safari 不提供运动传感器（必须 HTTPS）；
2. 即使 HTTPS，授权也必须在**用户手势**里发起并点「允许」，页面加载时自动调用会被拒绝；
3. 桌面浏览器没有传感器（可能仍报告 `kind=orientation`，但永远没有数据）。

**启用步骤**：

1. 用 HTTPS 打开（GitHub Pages 已是 HTTPS；或 WorkBuddy 分享链接 / 内网 HTTPS）；
2. 进幕后**轻点画面一次**触发授权（或在设定页加「开启体感」按钮，明确在手势内调用）；
3. iOS 还需在 设置 → Safari → 动作与方向访问 打开；
4. 验证：场景元素的 `data-spl-input` 变为 `orientation`；倾斜时 `.spl` 的 `transform` 有位移。

> 容器版走的是另一条链路（平台陀螺仪 `startGyroscope`），与本文无关。

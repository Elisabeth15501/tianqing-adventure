## 0. 一句话结论

**v1.1.5 就是被驳回的那一版**：它同时具备两个独立缺陷——① 打包时根目录多了一个 `assets-check.html` 抢走入口；② 所有 Canvas 小游戏（含投壶、史官线三关）**只监听 pointer 事件、完全没有 touch 监听**，在只投递 touch 事件的容器里等于整块画面点不动。此外真机首帧 `clientWidth=0` 会把三层视差场景压成 2×1 像素，表现为「部分场景/3D 素材没加载」。**因此回退到 v1.1.5 只适合作为基线冻结，不能直接重传** —— 会原样复现驳回。

## 3. 逐项排查（含证据）

### 3.1 打包入口（驳回 1）

- **机制**：打包器取 zip 根目录**第一个 `.html`** 当入口。当时根目录有 `assets-check.html`（字母序在 `index.html` 前），于是被判为入口。
- **证据**：`build_minitool.py` 注释与逻辑（`EXCLUDE_HTML = {'assets-check.html'}`，并在收尾断言 `html=['index.html']`）；本次重建输出 `sanity OK (15 js files, html=['index.html'])`。
- **风险**：该脚本是**未跟踪文件**。任何人重新打包、或换机克隆仓库，都会退回「两个 html」的旧行为 → 同一驳回复发。
- **建议**：把 `build_minitool.py` 入库，并在 CI/发布前跑 `sanity`（已在脚本内）。

### 3.2 输入通道（驳回 2，最高置信）

`js/minigame.js` v1.1.5 第 3348–3351 行：

```js
stage.addEventListener('pointerdown', onDown);
stage.addEventListener('pointermove', onMove);
stage.addEventListener('pointerup',   onUp);
stage.addEventListener('pointercancel', onUp);
```

**全文没有任何 `touchstart / touchmove / touchend` 监听。** 8 个 `rich` 小游戏（tang / shang / folk / lamp / shifood / shifolk / proof / touhu）全部走这一层 `TQM.play`，因此只要容器**不投递 pointer 事件、只投递 touch 事件**，这 8 个游戏就一起失效——画面能进、手指怎么按都没反应，正对「页面按钮无法点击」。

**实测（`_qa/v115_input_gap.cjs`，对 v1.1.5 源码）**：

| 注入方式 | 结果 |
|---|---|
| A 纯 `TouchEvent`（start→move→end） | `ph` 仍为 `aim`，`aim=null` → **完全无响应** |
| B `PointerEvent` 且 `pointerType:'touch'` | `ph→fly` → 有响应 |

即：v1.1.5 能否操作，**取决于容器用哪种事件投递触摸**。这是一条无法自证的赌注，必须两种都接。

### 3.3 舞台触摸行为（驳回 2 的叠加因素）

- `.iv-stage`（`css/app.css:205`）**没有 `touch-action`**，只有 `Canvas` 生成的 `<svg>` 内联了 `touch-action:none`。
- Chrome 61 下若该内联样式未生效/被覆盖，手指纵向拖动会被判为页面滚动 → 浏览器发 `pointercancel` → 这一段拖动作废，表现仍是「拖不动」。
- 同一个 `Canvas` 还用了 `inset:0`（`js/minigame.js:37`）——**`inset` 是 Chrome 87+ 语法**，宿主 Chrome 61 不认（项目自己的 `css/app.css:611` 就记着这条坑）。虽然同时写了 `width/height:100%` 不至于完全错位，但绝对定位的 `top/left` 落空会让 `<svg>` 的静态位置参与 flex 居中，指针坐标映射存在偏移风险。

### 3.4 场景「不加载」（驳回 3，最高置信）

`js/app.js` v1.1.5 第 705 行：

```js
var W = app.clientWidth || 1, H = app.clientHeight || 1;
```

- 真机进幕那一瞬若 `app.clientWidth === 0`（WebView 首帧尚未布局），`W` 取 `1`，`k = max(1/1500, …) ≈ 0.0016`。
- 结果：三层视差宿主被写成 **2×1 像素**，图其实下载成功了，但整块看不见。
- 受影响的正是走 parallax 的场景：**S1 横版 / S2 广德殿 / S5 滋德殿 / S7 瓷心**；S1 竖版、S3、S4、S6 是单层/长卷，不经此函数——所以症状天然是「**部分**场景没加载」。
- 桌面模拟器布局即时完成，`clientWidth` 从不为 0，因此**在模拟器里永远复现不出来**。这解释了「官方 emulator 正常、真机不正常」。

### 3.5 纹理上限闸门（3D 与长卷）

`js/assets.js`：

```js
var tooBig = TA.env && TA.env.tex2048 === false && Math.max(im.width, im.height) > 2048; // :213
if (TA.env.tex2048 === false) { return '当前环境纹理上限不足 2048px'; }                 // :307
```

`tex2048` 的探针会建一张 **2048×2048 canvas 再 `getImageData`**（`:141`）。低内存机型上这一步可能失败 → `tex2048=false` → 所有边长 >2048 的素材被**主动拒绝**。
本项目唯一的超标文件是 `assets/scenes/s4_pano/pano_l4.webp`（**2880×720**，303KB）→ S4 长卷在真机上可能整块空白。3D 图集 `vessel_ll.webp` 是 1920×480，不触发。

### 3.6 失败全静默（为什么"查不到报错"）

| 位置 | 行为 |
|---|---|
| `js/app.js` `mountScene()` catch | 直接移除宿主、退回矢量底图，**无日志** |

### 3.8 仍需排除的环境因素

1. **测的不是新包**：模拟器按 `app/<hash>` 缓存，旧包会残留 → 上传后清缓存重开。
2. **上传了错误的包**：误传 Pages 的 `dist`（含 `tilt-web.js` / `assets-check.html`）。
3. **机型 WebView 过旧**：低于 Chrome 61 时 `Promise`/`flex` 表现不同；建议记录机型 + 容器版本。

### P0-1 输入双轨（解决「点不动」）

`js/minigame.js`，把 3348–3351 的四行替换为「有 PointerEvent 就接所有 pointerType，否则退回 touch + mouse；两路互斥去重」：

```js
var USE_PTR = !!global.PointerEvent;
var ptrId = null, touchId = null;

function onDown(e) {
  if (USE_PTR && ptrId !== null) { return; }
  if (e.cancelable) { e.preventDefault(); }
  if (USE_PTR) { ptrId = e.pointerId; }
  g.down(cv.map(e));
  if (USE_PTR) { try { stage.setPointerCapture(e.pointerId); } catch (err) {} }
}
function onMove(e) {
  if (USE_PTR && ptrId !== null && e.pointerId !== ptrId) { return; }
  if (e.cancelable) { e.preventDefault(); }
  g.move(cv.map(e));
}
function onUp(e) {
  if (USE_PTR && ptrId !== null && e.pointerId !== ptrId) { return; }
  ptrId = null;
  g.up(cv.map(e));
}

/* touch 兜底：容器只投递 touch 事件时，这是唯一通路 */
function tPt(t) { return { clientX: t.clientX, clientY: t.clientY, pointerId: t.identifier }; }
function tDown(e) { if (touchId !== null || ptrId !== null) { return; }
  if (e.cancelable) { e.preventDefault(); }
  var t = e.changedTouches[0]; if (!t) { return; } touchId = t.identifier; g.down(cv.map(tPt(t))); }
function tMove(e) { if (touchId === null || ptrId !== null) { return; }
  if (e.cancelable) { e.preventDefault(); }
  var t = e.touches[0]; if (!t) { return; } g.move(cv.map(tPt(t))); }
function tUp(e) { if (touchId === null) { return; }
  touchId = null; var t = e.changedTouches[0];
  g.up(t ? cv.map(tPt(t)) : { x: 0, y: 0 }); }

if (USE_PTR) {
  stage.addEventListener('pointerdown', onDown);
  stage.addEventListener('pointermove', onMove);
  stage.addEventListener('pointerup', onUp);
  stage.addEventListener('pointercancel', onUp);
}
stage.addEventListener('touchstart', tDown, { passive: false });
stage.addEventListener('touchmove', tMove, { passive: false });
stage.addEventListener('touchend', tUp, false);
stage.addEventListener('touchcancel', tUp, false);
```

`destroy()` 里同步移除这四组监听。验收：`_qa/v115_input_gap.cjs` 的 A、B 两路都必须变成 `fly`。

### P0-3 场景宿主尺寸（解决「场景不见」）

```js
function fitSceneCover(host, key, form, tries) {
  if (!host) { return; }
  var cfg = (global.TQScenes && global.TQScenes.form) ? global.TQScenes.form(key, form) : null;
  if (!cfg || cfg.kind !== 'parallax' || !cfg.size) { host.style.cssText = ''; return; }
  tries = tries || 0;
  var W = app.clientWidth, H = app.clientHeight;
  if (!W || !H) {                       /* 真机首帧尚未布局：重试，绝不用 1 兜底 */
    if (tries < 24) { setTimeout(function () { fitSceneCover(host, key, form, tries + 1); }, 50); }
    else {
      W = global.innerWidth || 390; H = global.innerHeight || 844;   /* 最后兜底 */
      applyFit(W, H);
    }
    return;
  }
  applyFit(W, H);
  function applyFit(W, H) {
    var k = Math.max(W / cfg.size[0], H / cfg.size[1]);
    var w = Math.round(cfg.size[0] * k), h = Math.round(cfg.size[1] * k);
    host.style.width = w + 'px'; host.style.height = h + 'px';
    host.style.left = Math.round((W - w) / 2) + 'px';
    host.style.top = Math.round((H - h) / 2) + 'px';
  }
}
```

并在 `enterAct` 后监听 `resize` / `orientationchange` 重算一次。

## 5. 排查思路（下次如何一次定位）

1. **先分「没请求」还是「请求了没显示」**：在包内加一个 `?diag=1` 视图，打印 `TQA.env`、每个场景图的 `src / naturalWidth / onerror`。请求 200 而 `naturalWidth=0` ⇒ 解码问题；有请求但 DOM 尺寸为 2×1px ⇒ 宿主尺寸问题。
2. **输入通道计数**：手指按一下，打印 `pointerdown / touchstart / pointercancel` 的计数。只有 `touchstart` ⇒ 走 P0-1；有 `pointerdown` 但随即 `pointercancel` ⇒ 走 P0-2。
3. **用官方模拟器时进对 frame**：`redapp dev` 的游戏跑在跨域子 frame（`miniapp-sandbox.xiaohongshu.com/.../app/<hash>`），Playwright 要用 `page.frames()` 找它，主页面 `evaluate` 摸不到 `TQA`。
4. **模拟器只能证伪不能证真**：模拟器是桌面 Chromium，`clientWidth` 永不为 0、内存也够，所以 3.4 / 3.5 两类问题**只能在真机复现**。

# 上架优化方案：小红书小工具（优先） × GitHub Pages（常驻） × WorkBuddy（兜底/内测）
> 2026-11-04 · 基线 v1.1.5（tag `v1.1.5` / `b06946d`） · 目标版本 v1.1.10
> 依据：`docs/小红书小工具部署失败排查_v1.1.5基线.md` + `docs/双平台部署可行性评估_v1.1.5.md` + 平台官方规范

---

## 0. 决策摘要

**这不是三选一，是三层结构，且可以并行：**

| 层 | 平台 | 角色 | 当前状态 | 增量成本 |
|---|---|---|---|---|
| 主攻 | **小红书小工具** | 拿平台流量入口，用户不用跳浏览器 | v1.1.5 被驳回 2 次（原因已定位） | 4 处 P0 修复 + 打包纪律 |
| 常驻 | **GitHub Pages** | 对外展示、玩法验证、Web 端真实用户反馈 | v1.1.5 在线 | ≈0（同一份修复顺带修好手机端 bug） |
| 兜底 | **WorkBuddy** | 内测通道 / 上架受阻时的可分享链接 | 未发布 | **≈0**（`dist/` 直接可发，静态站） |

**关键判断：WorkBuddy 不要等"小红书失败"再启动。** 它是静态站、零改造，现在就能发一条内测链接，用真人反馈去验证那 4 处修复——反而能提高小红书一次过审的概率。**并行，不是串行。**

## 1. 小红书小工具：可行性判定

### 1.1 技术层面：**可上架**（阻塞点全部可定位到行、可修）

| # | 阻塞点 | 证据（v1.1.5 实际代码） | 修复 | 判定 |
|---|---|---|---|---|
| 1 | 入口 html 不唯一 | 根目录曾有 `assets-check.html` 排在 `index.html` 前 | 构建排除 + 断言 | 已闭环 |
| 2 | 小游戏点不动 | `minigame.js:3348-3351` 只绑 `pointer*`，**全文无 touch 监听**；实测注入纯 TouchEvent → `ph` 停在 `aim`、`aim=null` | 双轨输入 + `touch-action:none` | 必修 |
| 3 | 场景"不加载" | `app.js:705` `clientWidth \|\| 1` → 首帧为 0 时宿主被写成 **2×1px** | 量不到就重试，禁用 `1` 兜底 | 必修 |
| 4 | 长卷/纹理超限 | `s4_pano/pano_l4.webp` = **2880×720**，`assets.js:213` 在 `tex2048=false` 时主动拒绝 | 压到 2048×512 | 必修 |
| 5 | 失败静默 | `scenes.js` 裸设 `im.src` 无 `onerror`；`app.js:733` catch 不打日志 | 重试一次 + `console.warn` | 必修 |

> 这 5 条都**不涉及玩法重写**，全部是输入层、尺寸层、构建层。这是"可上架"的技术依据。

### 1.2 非技术闸门（代码消除不了，必须提前处理）

| 闸门 | 风险 | 处置 |
|---|---|---|
| **内容安全审核** | 33 张 AI 生成立绘 + 历史同人叙事（郭荣/柴荣双名、后周宫廷） | ① 自查：无政治敏感、无低俗、无封建迷信渲染；② 史料已在 `docs/史料核查_*.md` 有据；③ 准备好"世传/演义"标注话术 |
| **类目与主体** | 小工具类目是否对个人开放、是否需企业主体 | 上传时按平台提示确认；若要求主体资质，走 WorkBuddy 兜底 |
| **能力加白** | 云存档 §3.16 为内测；陀螺仪需客户端 ≥9.50 | 云存档已有 1005/1006 关闸降级，不加白也能玩；陀螺仪不可用自动退化为指针拖动 |
| **体积** | 6.29 / 10 MiB（已用 63%） | 后续素材按增量预算；>8 MiB 告警 |

### 1.3 Go / No-Go 规则（写死，避免情绪化决策）

**Go（提交送审）** 需同时满足：
1. 4 处 P0 修复完成，`_qa` 输入探针 A/B 两路均 `fly`
2. `redapp dev` 进 frame 驱动：7 场景 × 2 形态 0 坏图 + 3D 未回退矢量
3. 真机（`redapp preview` 扫码）走通：首幕 → 投壶 → 史官三关 → 终幕
4. 打包断言全绿（单入口、禁用 API=0、体积 <8 MiB）
5. 内容自查表逐条打勾

**No-Go（转 WorkBuddy 为主）** 任一成立：
- 同一类驳回连续出现 2 次且无法复现（说明是宿主黑盒限制）
- 内容审核不通过且无法通过改文案/换图解决
- 类目/主体资质不满足

## 2. 小红书适配要点（逐条可执行）

### 2.1 输入层（决定"能不能玩"）

```js
// minigame.js · TQM.play 内
var USE_PTR = !!global.PointerEvent;
var ptrId = null, touchId = null;
// 有 PointerEvent：接所有 pointerType（mouse/pen/touch）+ setPointerCapture
// 同时无条件挂 touchstart/move/end({passive:false})，两路互斥去重
```

- 不按 `pointerType` 过滤（v1.1.6 曾反向踩坑：把 `touch` 指针全丢）
- `{passive:false}` 才能 `preventDefault`，否则拖动被判滚动 → `pointercancel`
- 舞台 `touch-action:none`（`.iv-stage`，`css/app.css:205`）

### 2.2 尺寸层（决定"看不看得见"）

- `Canvas` 的 `inset:0` → `left/top/right/bottom`（Chrome 61 不认 `inset`）
- `fitSceneCover`：`clientWidth` 为 0 时 `setTimeout` 重试（≤24 次 × 50ms），最后用 `innerWidth/innerHeight`；`resize`/`orientationchange` 重算
- 长卷 `pano_l4` 2880×720 → **2048×512**，`scenes.js` 的 `world` 同步改 2048

### 2.3 运行时能力（决定"合不合规"）

| 能力 | 正确用法 | 降级 |
|---|---|---|
| 存储 | `setStorage/getStorage` 优先，JSON 字符串，单 key ≤1MB | bridge 失败 → `localStorage` → 内存（`storage.js` 已有三层） |
| 陀螺仪 | 先 `onGyroscopeChange(fn)` 再 `startGyroscope({interval:'ui'})`；版本取 `launchOptions.miniToolEnv.buildVersion` 且 `floor(/1000)≥9500`；退场 `stop`+`off` 双清理 | 失败静默 → 指针拖动 |
| 关注 | `followAuthor` 判空 + errCode 降级（20002 静默 / 15404 频控提示 / 10003 忽略） | 不展示入口 |
| 云存档 | `addCloudStorage` 等；遇 1005/1006 关闸隐藏 | 本地存档照常 |
| 安全区 | `getWindowInfo` 取 insets，或 `var(--safe-area-inset-*, env(...))` | 0px |

**绝对禁止**（容器内）：`fetch`/`XHR`/`WebSocket`/`DeviceOrientationEvent`/`devicemotion`/`geolocation`/内联 `<script>`/外链资源。

### 2.4 打包纪律

```
zip 根 = index.html（唯一 html，且为第一个条目） + mini_tool.json + 资源目录
排除：js/tilt-web.js、assets-check.*、.bak、node_modules
断言：html==['index.html']；names[0]=='index.html'；禁用 API=0；体积<10MiB
```

### 2.5 版式与性能

- 全屏手机布局：不套 Pages 的 900/780/620 居中壳
- 矮屏（≤720px 高）：舞台 168，按钮两个并排 + 主按钮独占一行
- 预算：30 FPS、纹理 ≤2048、单图 ≤300 KB、总量 <8 MiB

## 3. WorkBuddy 兜底方案（零改造）

### 3.1 为什么是零改造

WorkBuddy 发布支持**静态站**：上传目录 → 内部 HTTP 服务 → 返回分享链接。我们的 `dist/` 已经是纯静态、全相对路径、无服务端依赖，**直接可发**。

### 3.2 操作要点

| 项 | 值 |
|---|---|
| `directory` | **`<repo>/dist`**（不要用仓库根：会带上 `.git` 与数百 MB 草稿 PNG） |
| `language` | `static` |
| `appName` | 「天清往事」（≤12 字） |
| `entryHtml` | 建议显式传 `index.html`（目录内还有 `assets-check.html`，多页时服务端无法自动判断归属） |
| 发布语义 | **覆盖式**：同一目录再发 = 覆盖原链接，链接保持不变 |

### 3.3 注意事项

- 每次 Web 发布都需要用户**当轮明确同意**（不是一次授权永久有效）
- 链接是分享链接，不等同于"应用商店上架"，无自然流量
- 无自定义域名、无 CDN 控制、无 SEO
- 有云端登录/云服务需求时，发布目标与云服务实例绑定，**不要换目录**（换目录 = 换 app = 换链接）
- 下线用 `unpublish`，链接立即失效

## 4. 三平台对比

| 维度 | 小红书小工具 | GitHub Pages | WorkBuddy |
|---|---|---|---|
| 托管形态 | 平台内小工具（包） | 静态站（gh-pages 分支） | 静态站（上传目录） |
| 用户入口 | 小红书内，有平台流量 | 需外部链接/搜索 | 分享链接，无自然流量 |
| 体积上限 | **10 MiB 硬上限** | 1 GB（软带宽 100GB/月） | 未见硬性体积限制，按上传包体 |
| 网络能力 | **全禁** | 可 fetch/CDN | 可 fetch（沙箱可联网） |
| JS 基线 | Chrome 61 级 WebView | 现代浏览器 | 现代浏览器 |
| 平台 API | Storage/关注/云存档/陀螺仪 | 无（用 Web 等价物） | 无 |
| 审核 | **内容安全 + 类目** | 无（GitHub ToS） | 无 |
| 更新方式 | 重新打包上传 | 推 gh-pages | 重新发布（覆盖） |
| 自定义域名 | 无 | 支持 | 无 |
| 改造成本 | P0 四项 + 构建纪律 | 0（共用修复） | **0** |
| 主要失败风险 | 审核/宿主黑盒 | 无 | 账号/配额/沙箱故障 |

## 5. 共享代码方案（一次改造，三处受益）

```
js/platform.js        新增：唯一平台判定（能力探测，非 UA）
  ├ name / inContainer
  ├ has(api)
  ├ save/load（复用 storage.js 三层降级）
  ├ safeArea()
  ├ gyro()（容器只走平台陀螺仪；web 才允许 tilt-web.js）
  └ follow()/cloud()（非容器为 no-op）

build_packages.py --target pages|workbuddy|minitool
  pages     → dist/      （index.html + assets-check.html + tilt-web.js + .nojekyll）
  workbuddy → dist/      （同上，直接复用；可省 .nojekyll）
  minitool  → minitool/  （单入口；排除 tilt-web.js / assets-check.*；写 mini_tool.json）
```

**改造顺序（风险从低到高）**：

1. 先修 P0（纯 bug 修复，三平台都受益）
2. 再抽 `platform.js`（纯重构，7 处判定收敛）
3. 最后统一构建（同一脚本三 target + 同一套断言）

> 顺序不能反：先重构再修 bug，会把"行为变化"和"结构调整"混在一起，出问题时无法二分定位。

# 双平台部署可行性评估：GitHub Pages × 小红书小工具
> 2026-11-04 · 基线 v1.1.5 · 依据：仓库实测 + 官方规范（`minitool-zip-builder/references/*`、GitHub Pages 限额文档）

## 0. 结论

**可行，而且已经是既成事实**——同一仓库已经产出两个平台各自的包，且两份产物 **93.5% 文件完全相同、99.8% 字节相同**。

但**"同一份产物传两个平台"不可行**：容器强制单入口、禁网络、禁一批浏览器 API；Pages 需要诊断页与 web 版姿态源。结论是：

> **共享源码，不共享产物。** 一个源 + 两个构建目标 + 一层平台适配，是唯一可持续的形态。

当前最大的问题不是复用率（已经很高），而是**平台判定散落在 7 处、产物无联合校验、修复只在其中一个产物里生效**——这才是 v1.1.5~v1.1.9 反复出事的结构性原因。

## 1. 实测：两个产物到底差多少

| 指标 | dist（Pages） | minitool（容器） |
|---|---|---|
| 文件数 | 154 | 153 |
| 体积 | 6.90 MB | 6.90 MB |
| 根目录 html | `index.html` + `assets-check.html` | **仅** `index.html` |
| 独有文件 | `js/tilt-web.js`、`assets-check.html` | `mini_tool.json` |

| 逐字节相同 | **144 / 153** | |

> 另有 6 个 js/css 文件大小不同，经行尾归一化比对**内容完全一致**——是 `core.autocrlf=true` 造成的 CRLF/LF 差异，不是逻辑漂移。这条要写进构建断言，否则每次比对都会被噪声干扰。

**共享率：按文件 93.5%，按字节 99.8%。** 复用的天花板已经接近，剩下的 0.2% 全是平台边界。

## 2. 平台约束对照

| 维度 | GitHub Pages | 小红书小工具容器 | 对本项目的实际含义 |
|---|---|---|---|
| 托管 | 静态文件，HTTPS，子路径 `/tianqing-adventure/` | 包内本地文件，沙箱路径 `/files/…` | 只能用**相对路径**；任何以 `/` 开头的绝对路径必坏 |
| 体积 | 站点 ≤1 GB；月带宽软限 100 GB；每小时 ≤10 次构建（自定义 Actions 不受限）；部署 >10 分钟超时 | **zip ≤10 MiB（硬上限）**；建议 ≤2 MiB；单文本 >2 MiB 告警 | 6.29 MB 在容器里还剩 ~3.7 MB；**这是真正的天花板** |
| 入口 | 任意 html，可有多个 | **根目录唯一 `index.html`，且须为第一个条目** | 诊断页只能留在 Pages |
| 网络 | 可 fetch / XHR / CDN | **禁止** `fetch`/`XHR`/`WebSocket`/`EventSource`/外链资源 | 所有素材必须随包；不能做在线更新、埋点、远程配置 |
| JS 基线 | 现代浏览器 | WebView（项目按 **Chrome 61 / ES2017** 设防） | 禁 `?.` `??` `inset:` `aspect-ratio` `:has()` `clamp()` flex-gap |
| 安全策略 | 无 CSP 限制 | `script-src` 不含 `unsafe-inline` | 禁内联 `<script>`、行内事件 |
| 设备能力 | 浏览器全套 | 平台白名单 API（`getWindowInfo`/Storage/关注/云存储/陀螺仪…） | 平台外能力一律判空 + 降级 |
| 姿态/陀螺仪 | `DeviceOrientationEvent`（iOS 需手势授权） | **禁用** `DeviceOrientationEvent`/`devicemotion`；用 `startGyroscope`（需客户端 ≥9.50） | 必须**分文件**：`tilt.js`（容器/通用）+ `tilt-web.js`（仅 Pages） |
| 存储 | `localStorage` | `setStorage/getStorage`（bridge 优先，单 key ≤1 MB） | 已有三层降级：bridge → localStorage → 内存 |
| 版式 | 桌面 900/780/620 居中壳 + 横版媒体查询 | 手机全屏，需安全区 | 桌面壳不能带进容器（会把画面缩成一条） |
| 内容审核 | 无（仅 GitHub ToS） | 平台内容安全审核 | AI 生图 / 历史同人会单独过审 |
| 私有性 | 仓库私有 ≠ 站点私有 | 包内自洽 | Pages 站点公开可被扒素材 |

## 4. 必须分叉的差异点（只有 5 类）

1. **构建产物与入口**
   - Pages：`dist/`，含 `assets-check.html`、`js/tilt-web.js`
   - 容器：`minitool/`，**排除**两者，写 `mini_tool.json`，单入口断言

2. **资源路径与路由**
   - 全部相对（`assets/…`、`./js/…`），不用前导 `/`
   - Pages 需 `.nojekyll`（防 Jekyll 跳过 `_` 开头目录）；容器不需要，但容器会按 `app/<hash>` 缓存旧包

3. **平台专属 API 与权限**
   - 容器：`xhs.miniTool.*`（Storage / 关注 / 云存储 / 陀螺仪 / `getWindowInfo` 安全区）
   - Pages：`localStorage`、`deviceorientation`、`keydown`
   - **禁用项**只能在 Pages 侧出现 → 物理分文件，不靠运行时 if

4. **输入模型**
   - 两端都用 Pointer + Touch 双轨（容器可能只投递 touch；Pages 桌面用鼠标）
   - 舞台 `touch-action:none`；禁依赖 hover

5. **版式与性能预算**
   - Pages：桌面居中壳、横版媒体查询、可 60 FPS
   - 容器：全屏手机 + 安全区、30 FPS 目标、纹理 ≤2048、内存更紧

## 5. 共享方案（推荐）

### 5.1 目标结构

```
src/（现状不变，仍是 js/*.js 无构建）
├── js/platform.js        ← 新增：唯一平台判定 + 能力探测
├── js/tilt.js            ← 通用（容器内不请求 web 姿态源）
├── js/tilt-web.js        ← 仅 Pages，构建时排除出 container 包
├── js/storage.js         ← 只调 P.storage
└── …

build_packages.py         ← 合并 build_site.py + build_minitool.py
├── TARGET=pages   → dist/      （含诊断页、tilt-web.js、.nojekyll）
└── TARGET=minitool → minitool/  （单入口、排除禁用文件、mini_tool.json）
```

### 5.2 `platform.js` 契约（唯一判定点）

```js
(function (global) {
  'use strict';
  var mt = (global.xhs && global.xhs.miniTool) || null;

  var P = {
    name: mt ? 'minitool' : 'web',
    inContainer: !!mt,

    /* 能力探测而非 UA 判断 */
    has: function (api) { return !!(mt && typeof mt[api] === 'function'); },

    /* 存储：容器 bridge 优先，web 用 localStorage；失败一律降级不抛 */
    save: function (k, v, cb) { /* storage.js 现有三层逻辑上移到这里 */ },
    load: function (k, cb) { /* … */ },

    /* 安全区：容器取 getWindowInfo，web 读 CSS env() */
    safeArea: function () { /* 返回 {top,bottom} */ },

    /* 姿态：容器只走平台陀螺仪；web 才允许加载 tilt-web.js */
    gyro: function () { /* 容器内 return null，绝不碰 DeviceOrientationEvent */ },

    /* 关注/云存档等容器专属，web 侧为 no-op */
    follow: function (cb) { if (!mt || !P.has('followAuthor')) { cb && cb('unsupported'); return; } }
  };

  global.TQP = P;
})(window);
```

改造点（现在散落的 7 处）：
`app.js:85 / 1766 / 1794 / 1804`、`storage.js:14`、`cloudsync.js:21`、`tilt.js:79-82`、`tilt-web.js:18` → 全部改为读 `TQP`。

**收益**：容器禁用 API 的"是否触碰"从"靠自觉"变成"只有 tilt-web.js 一个文件会碰，而它不进包"。

### 5.3 一份白名单驱动两个产物

```python
TARGETS = {
  'pages':    {'entry': ['index.html', 'assets-check.html'],
               'js_exclude': set(),
               'extra': ['.nojekyll']},
  'minitool': {'entry': ['index.html'],
               'js_exclude': {'tilt-web.js', 'assets-check.js'},
               'extra': ['mini_tool.json']},
}
```

构建后统一断言（两个 target 都跑）：

```
[ ] 无 <script> 内联 / 行内事件 / type=module
[ ] 无 https:// 外链、无 iframe
[ ] 无 fetch / XHR / WebSocket / DeviceOrientationEvent（仅 minitool）
[ ] minitool: html 列表 == ['index.html'] 且 names[0] == 'index.html'
[ ] 所有 js 通过 node --check
[ ] assets 数量 = 33/29/49，scenes 十目录齐全
[ ] 体积：minitool ≤ 10 MiB（建议阈值 8 MiB 告警）
```

## 6. 主要风险

| # | 风险 | 现状 | 影响 | 处置 |
|---|---|---|---|---|
| 1 | **平台判定散落 7 处** | 已存在 | 改一处漏一处；禁用 API 可能被带进容器包 | 引入 `platform.js`，判定收敛为一处 |
| 2 | **双产物漂移** | dist 停留在 11-02，靠行尾巧合才"一致" | Pages 与容器行为不同，问题只在一边复现 | 同一脚本双 target，构建时间戳写进包 |
| 3 | **修复只在一边生效** | v1.1.7~1.1.9 的修复只进了 minitool 包，源码回退后全丢 | 同样的 bug 在 Pages 又出现 | 源码单一事实源 + tag 发布；包可随时重建 |
| 4 | **禁用 API 被 Pages 专属文件带入** | `tilt-web.js` 曾被打进容器包 | 静态扫描命中 → 驳回 | 构建期物理排除 + 扫包断言 |
| 5 | **单入口被诊断页破坏** | 已踩过一次 | 直接驳回 | 断言 `html==['index.html']` |
| 6 | **体积逼近上限** | 6.29 / 10 MiB | 再加素材就超 | 素材预算：新增先算增量；长卷压到 2048 |
| 7 | **内容审核差异** | AI 生图 + 历史同人 | 容器可能被内容审核拦；Pages 不会 | 送审前单独过审；保留可替换素材层 |
| 8 | **Pages 站点公开** | 仓库私有但站点公开 | 美术资产可被直接下载 | 可接受则不动；介意则加水印/降质图 |
| 9 | **缓存导致"改了没生效"** | 容器按 `app/<hash>`；Pages 走 CDN | 排查时误判 | 版本标显示在设定页；Pages 加 `?v=` |

## 7. 推荐做法（按顺序）

1. **先收敛判定**：新增 `platform.js`，把 7 处 `window.xhs` 判定改成一个入口（纯重构，不改行为，两端都要回归）。
2. **再合并构建**：`build_packages.py --target pages|minitool`，两个 target 跑同一套断言；`.nojekyll` 与 `mini_tool.json` 由 target 决定。
3. **输入层只写一次**：Pointer + Touch 双轨 + `touch-action:none` 作为**两端共用**实现（Pages 桌面用鼠标也走 pointer，不冲突）。
4. **平台专属能力物理隔离**：容器专属 API 只允许出现在 `platform.js`；Pages 专属（`tilt-web.js`、诊断页）只允许出现在 pages target 的文件清单里。
5. **发布纪律**：`vX.Y.Z` tag = 源码；两个包都从该 tag 重建；包内 `version.js` 写死后不允许手工改。
6. **回归矩阵**（每次发版）：
   - Pages：桌面 1280×800、手机 390×844 各走一遍首幕 + 投壶 + 史官三关
   - 容器：`redapp dev` 进 frame 驱动 + `redapp preview` 真机扫码
7. **体积门禁**：minitool >8 MiB 告警、>10 MiB 阻断。

---

## 8. 一句话

**代码复用不是问题（99.8% 已经共享），平台差异只有 5 类、且都是"文件级"而非"逻辑级"的。**
真正要改的是工程纪律：**一个判定入口、一个构建脚本、一套断言**——否则每次修 bug 都会变成"修好容器、坏了 Pages"。

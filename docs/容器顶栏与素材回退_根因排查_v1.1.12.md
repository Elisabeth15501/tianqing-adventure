## 1. 问题一：顶栏太高 / 按钮被平台胶囊遮挡

### 根因链

```
getWindowInfo 旧实现只认 Promise（if !pr.then return）
  → 容器/后台预览走回调形态，拿不到结果
  → --tq-top-inset 恒为 0
  → .app 的 padding-top: var(--tq-top-inset) 不下移
  → 平台右上角胶囊（···、○）压住自绘顶栏的「设定 / 手札 / 进度条」
```

### 为什么普通网页正常
网页没有平台胶囊，也没有 `window.xhs.miniTool`，这段逻辑根本不触发；顶栏按原样布局即可。

### 修复
- `app.js` 的 `getWindowInfo` 改为**回调 + Promise 双形态**都接（先传 `{success,fail}`，兼容 Promise 返回）。
- 容器内顶部预留取 `max(实测 top, 44)`；Pages 仍为 0。
- **只由 `.app` 的 padding-top 下移**，不再给 `.topbar` 加 margin——中途试过，与 padding 叠加成双份下移，已回退。

容器桩实测：`--tq-top-inset=47px`、`--tq-set-top=63px`、`.app` padding-top `47px`、`.topbar` margin-top `0px`。

## 2. 问题二：大量场景 / 立绘 / 瓷片未载入（红角标「立绘未载入 · 自检」）

### 红角标触发条件
`portraits.js:883 markMissing()` 只在 `resolve` 返回 `stt==='fail'` 时挂。
`assets.js` 里 `fail` 是**永久缓存**的（`TA.status[key]='fail'`，之后 `resolve` 直接 `cb('fail')`），所以一旦某张图失败，整局都不会再试。

### 根因链

```
旧 imgs 永久缓存全部解码位图
  · 33 张立绘 ≈ 176 MiB
  · 49 张瓷片 ≈ 131 MiB
  · 合计理论峰值 ≈ 300 MiB+（RGBA8 估算）
  → 桌面浏览器无感，小工具 WebView 内存吃紧
  → 新图解码 onerror → finish('fail')
  → status 永久缓存 fail + 矢量回退 + 红角标
```

### 已排除的误判
- 路径大小写 / 文件名：注册表 83 条引用逐条比对，仅可选 `s8_scroll` 缺失。
- WebP 编码 / 尺寸：场景背景与部分立绘是真图，说明 WebP 基本可用；111 张 WebP 全部 ≤2048。
- 外链 / CSP 外部资源：无外部 URL。
- 场景预热：受控（`conc:1` + 延迟 1.2s + 只当前形态），不是内存元凶。

### 次要风险
`paintReal` 旧代码用 `im.src` 的**绝对 URL** 再建 `<img>`；容器 CSP 下绝对 URL 可能被二次拒绝。

### 修复
- `assets.js`：路径常驻（`srcs`）+ 位图 LRU（`imgs`，容器上限 6 / 网页 20）；被淘汰的图再次需要时，`resolve` 按相对路径静默重载。
- `portraits.js`：全部改用 `TQA.src(ak)` 相对路径上图，落图后 `release` 位图。
- 覆盖路径：单人 `bindSlot`、双人 `bindStage`、回忆容器 `mem-fig` 都走同一条 `show → resolve → paintReal/markMissing`，无第二套独立加载逻辑。

容器桩实测：8 张立绘并发后 LRU=6、`imgs`=6、`srcs` 全在；释放一张后再 `resolve` → `ok` 且位图重载成功；打包产物冒烟 0 异常。

## 3. 为什么"网页正常、容器不行"

两个触发条件在网页都不成立：
- 内存充足 → 位图不超限 → 不会 onerror → 不会 fail；
- 无平台胶囊 + `getWindowInfo` 不触发 → 顶栏按原样布局。

所以这不是"网页那套逻辑错了"，而是两套运行环境的边界差异。

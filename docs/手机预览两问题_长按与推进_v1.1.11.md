# 手机预览两问题：排查与修复（v1.1.11）
> 2026-11-11 · 基线 v1.1.10 · 环境：本地 `dist/` 经 LAN 预览（iPhone Safari / 桌面 Chromium+WebKit 对照）

## 1. 长按道具 → 选中文字

### 现象
长按面团/道具约 0.5s，iOS 弹出「复制 / 分享 / 全选 / 搜寻」菜单，并留下文字高亮。

### 为什么原来的防护没挡住
v1.1.5 起有两道防线，但都只覆盖「部分情况」：

| 已有措施 | 覆盖范围 | 漏在哪 |
|---|---|---|
| `.app *{-webkit-touch-callout:none; user-select:none}` | `.app` 的**后代元素** | 选择可以从 `html` / `body` 起手（例如拖到留白、或从舞台边缘起选），这些节点不在 `.app` 内 |
| `contextmenu` preventDefault | 安卓 WebView 的长按菜单 | iOS 的**文本选择**不走 `contextmenu`，它先建选区再弹菜单 |
| `.app img{pointer-events:none}` | `<img>` 节点 | 小游戏的道具与读数是 **SVG**，`<text>` 在 Safari 里可被单独选中 |

### 修法（三层一起，缺一层就会漏）
1. **CSS 扩到根节点**：`html,body` 与 `.app svg / .app svg text` 一律 `user-select:none` + `-webkit-touch-callout:none`；
2. **`selectstart` 直接 `preventDefault`**：选择根本不许开始（输入框除外）；
3. **`selectionchange` 兜底**：老 WebKit 若仍建了选区，立刻 `removeAllRanges()`，不留高亮与菜单。

另外把 `.iv-stage svg text` 设为 `pointer-events:none`——读数是纯展示，长按不该"按到字"上。

### 代价
全站正文不可复制（含史料卡/手札）。本作没有「长按复制」的需求，判定为可接受；若将来要开放，给对应容器加 `[data-selectable]` 白名单即可。

## 2. 完成第一个动手小节后无法推进

### 先排除「流程死锁」
用 headless 逐屏驱动（Chromium + WebKit），把女官线的 揉面→擀面→切面 全做完：

- `finishStep` 正常交棒（`si` 递增、`cb` 触发、`iv` 销毁、进入下一步）；
- 切面 2/2 后出现 `.mg-sheet`「继续」面板，`elementFromPoint` 命中的就是 `.mg-sheet-go`（**没有被遮挡**），点一次即关闭 `iv`、进入瓷片卡；
- 史官线（研墨起手）同样能过。

**结论：不是剧情数据/状态机死锁。** 若真是数据问题，headless 也会卡在同一处——它没卡。

### 真正的原因（两条叠加，都发生在 iOS）
1. **按住被系统打断**：揉面/擀面/投矢都是「按住」类操作。iOS 长按先起文本选择（见问题 1），选区一建立，这一下的指针序列就被取消——`pointerup` 收不到，按压不计入，小节永远做不满；
2. **完成面板只挂 `click`**：`mg-sheet` 原来只在 `click` 上确认。系统菜单/Callout 打开时，**第一次点击只用于关闭菜单**，不会派发 `click`。玩家点一下没反应，就认为「卡住了」。

两条合起来正好解释「做完第一节就推不动」，也解释了为什么模拟器/桌面测不出来。

### 修法
- 问题 1 的「选择封死」直接消除了第 1 条；
- `makeSheet` 改为 **`pointerdown` 记起点 + `pointerup` 确认**（一次性 `fired` 守卫，`click` 仅作无障碍兜底）。这样第一下就生效，也不会因为 `pointerup`+`click` 双触发而跳步；
- 起点判定 `inBox`：切面的拖动会一路划到舞台下缘、正好压过面板，必须确认「按下也落在面板内」才确认；
- `.mg-sheet` 的 `z-index` 5→7，并加 `touch-action:manipulation`。
